# ChatGPT Sites試行版

作業ブランチは`codex/chatgpt-sites`。ローカル版の採点・収集処理と生成済み画面をそのまま使い、Pythonの配信処理をSitesのWorkerへ置き換えます。パッケージの追加取得は不要です。

ローカルで配備準備・ニュース配信を行う場合はNode.js 22以降を用意し、`node --version`で確認してください。

## 初回登録

1. 登録IDがある場合は、公式Sites機能で所有者を確認する。自分のSiteなら再利用する。
2. 配布元・他人の登録情報が残っている場合は、別の作業用コピーを用意する。そのコピー内の`.openai/hosting.json`の`project_id`と`sites/registered-site.json`を未登録状態に戻す。元のSiteは変更しない。
3. 公式Sites手順で登録し、返されたIDを保存してから`node scripts/build-sites.mjs`でWorkerを作成し、所有者限定で配備する。依存取得が必要なら先に依頼者へ確認する。
4. Sitesツールが使えなければ、ソースZIPとWebの作成画面へ貼る依頼文を渡す。ZIPへ認証情報・`.git/`・`tmp/`・`node_modules/`を含めない。
5. 登録ID・URLと確認結果を返す。未認証での拒否、所有者の表示、JSON更新と読み戻しを確認する。

## 登録情報をローカルへ戻す

Webで登録した場合は、公式の登録結果をフォルダーを開いたローカルCodexへ渡し、次を保存します。

| ファイル | 保存する値 |
| --- | --- |
| `.openai/hosting.json` | 返されたIDを`project_id`へ保存。既存の保存領域の設定は維持する |
| `sites/registered-site.json` | 同じIDを`projectId`、正規のSiteオリジンを`origin`へ保存する |

自分のSiteであることと両ファイルの一致を確認してから、ローカルから配信してください。WebのチャットはPCのフォルダーを直接更新しません。

## ローカルで確認する

```powershell
node scripts/build-sites.mjs
node --test tests/sites.test.mjs
node scripts/sites-preview.mjs
```

画面ソースを変更した場合は、先に[画面の編集](../docs/development.md#画面の編集)に従って`node scripts/build.mjs`で`web/`を更新してください。`build-sites.mjs`は生成済み画面を取り込む処理で、画面ソースのビルドは行いません。

確認先は <http://127.0.0.1:8768/> です。既存のローカル版は8767のままです。

試行用の保存先は`tmp/sites-preview/`で、本来のニュース・設定を書き換えません。8768の画面はSites向けWorkerを動かしていますが、ホスト先の認証・R2・配備の検証にはなりません。

## ホスト先の構成

- `.openai/hosting.json`はR2の`BUCKET`を宣言します。公式の登録結果を`project_id`へ保存済みです。同じ応答で確認したIDとオリジンを`sites/registered-site.json`の`projectId`・`origin`にも保存しています。
- `dist/server/index.js`が配備用のESモジュールです。画面のHTML・CSS・JavaScriptと初回データを含みます。ソース全体や`tmp/`を配信しません。
- ニュースと設定はR2の`state.json`に保存します。保存済みデータを初回データより優先するため、画面を再配備してもデータは戻りません。
- 既知用語はSitesの利用者ID別に保存します。
- 設定とニュースはETagの条件付き保存を使い、同時更新による上書きを拒否します。

## 閲覧・更新の制限

この試行版は**所有者だけが利用する非公開Site専用**です。全パスの認証・認可をSitesの配信境界で実施します。ニュース更新はSitesが提供するサービスアクセスを使用します。更新APIに独自の公開認証機能はありません。

第三者へ共有する前には、閲覧と設定・ニュースの変更権限を分けて実装・検証してください。現在のコードのまま公開範囲を広げないでください。認証情報はソース、JSON、ブラウザー、実行プロンプトへ保存しません。

## ニュースJSONだけを更新する

1. フォルダーを開いたローカルCodexで、公式`get_site`から登録ID・オリジン・所有者限定設定を照合する。
2. Siteの最新設定を取得し、ローカル設定との差分を確認する。Siteを正本とする場合は、ローカル設定をバックアップして同期する。正本を判断できない場合は更新を保留する。
3. `nv-news-research`で収集・独立レビュー・採点し、`data/news.json`を更新する。不足・検証失敗なら配信しない。
4. 同じSiteのサービスアクセスを一時的に取得し、`scripts/upload-sites-news.mjs`へ標準入力で`serviceToken`を渡す。秘密値をコマンド引数・ソース・予約の依頼文へ保存しない。
5. スクリプトの保存・読み戻し結果と、画面の更新日時を確認する。

処理はローカルで既存のPython検証・採点を再実行し、保存済みJSONとの一致を確認します。次にSiteの設定の版を取得し、`PUT /api/news`でJSONを保存した後、同じJSONを読み戻して確認します。Workerでも異なる収集設定・配点、範囲外の点数、期間内記事を持たない話題、最低件数不足、古い生成日時への巻き戻しを拒否します。Worker自体は点数を再計算せず、Python生成・独立レビュー済みのファイルを信頼します。画面は既存の2秒間隔の取得で反映し、再ビルド・再配備は不要です。

設定の同期はCodexへの依頼に含めます。配信スクリプト自体に設定を同期する機能はありません。

定期実行は、実Siteでサービスアクセスによる更新と読み戻しを確認してから設定します。ローカルフォルダーを使う実行ではPCとアプリが起動している必要があります。クラウド実行ではソース・Skill・必要な更新権限へ継続的にアクセスできる構成が別途必要です。
